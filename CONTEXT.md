# Предметная модель DLEToolbar

- **Панель** — элементы управления сайтом в собственном Shadow DOM. Доступ определяется выбранными группами DLE; выбрать можно только группы с `allow_admin`.
- **Место вывода** — маркер добавляется к `{AJAX}` и заменяется панелью только в `engine/modules/main.php`. Печать (`mod=print`), RSS, Дзен и Турбо (`mod=rss`), предпросмотр, offline и бан завершаются в `init.php` до `main.php`; ajax и антибот (`controller=ajax|antibot` в DLE 21, `engine/ajax/controller.php` в старых версиях) не проходят через `init.php`; `sitemap.xml` — статический файл. Поэтому в этих ответах панели нет без отдельных проверок. При печати страницы браузером `:host` скрывается правилом `@media print` внутри Shadow DOM; оно с `!important` сильнее стилей шаблона.
- **Всплывающее окно** — SQL-панель, лог и файлы или меню выбора шаблона. В одной панели одновременно открыто только одно окно. Переключение закрывает предыдущее сразу, без возврата фокуса.
- **Жизненный цикл всплывающего окна** — открытие, закрытие, отмена отложенного закрытия, состояние видимости и ARIA, координация общей подсказки. Его реализация принадлежит `ComponentFramework/PopupLifecycle`.
- **Лог и файлы** — один компонент `Files` с единым представлением таймлайна на базе `DebugLog`: хронологический список ручных и автоматических отметок со временем от начала запроса, относительными интервалами, длительностью парных подключений, бейджами статуса кэширования («из кэша» / «не из кэша») и раскрывающимся по клику списком файлов, подключённых на соответствующем шаге (`details/summary`). `DebugLog::add()` доступен после автозагрузчика, сохраняет ранние записи до проверки доступа, файл и строку без аргументов стека. После проверки доступа и инициализации всех видимых компонентов `DLEToolbar::init()` запускает сбор файлов только при видимом `files`. Порядок кнопок не меняет начало замеров. Патчи before/after в `engine/init.php` окружают include `engine/engine.php`; вывод панели закрывает журнал. Ручные отметки сохраняют дельты подключённых файлов и интервалы. `hrtime()` измеряет интервалы, `get_included_files()` фиксирует новые уникальные пути. Пути кэшированных файлов сопоставляются оригиналам по карте DLE в списке файлов, в отметках и SQL; признак нахождения в кэше сохраняется и отображается бейджем; номер строки относится к исполняемой копии. Если соответствия нет, показывается фактический путь. Снимки хранят физические пути, чтобы не смешивать разные подключения. После снимка журнал заморожен. Всё состояние живёт только в текущем запросе.
- **SQL-панель** — просмотр, копирование и сворачивание запросов. В DLE ≥ 14.0 при видимом компоненте и включённом экспериментальном параметре `trace_sources` (по умолчанию выключен) после проверки доступа хук `Queries::initialize()` заменяет `db->query_list` объектом `QueryLog`: объект `db` и его методы остаются штатными, поэтому сохранённые ссылки на `$db` и страница ошибки MySQL работают как прежде, а к новым записям добавляется файл:строка вызова. Сторонний код, который обрабатывает `query_list` функциями массивов, при включённом параметре получит объект вместо массива. Поля существующих записей можно менять через индекс; чтение отсутствующего индекса выдаёт штатное предупреждение PHP и возвращает `null`, не меняя журнал. Новые записи нужно добавлять через `[] =` или присваивать целиком по индексу. Общий `SourcePath` сопоставляет копии из кэша плагинов исходным путям через приватную карту `DLEPlugins`; строка относится к исполняемой копии. Подпись модуля/плагина определяется по пути. По этой подписи (инициатору) список фильтруется кнопками под заголовком панели с числом запросов и суммарным временем; DLE идёт первым, остальные — по убыванию времени, запросы без источника — последними. Каждому инициатору в порядке фильтра назначается свой оттенок (`--query-hue` на строке, группе и кнопке фильтра с классом `query-tinted`): сначала фиксированная палитра, затем оттенок, наиболее удалённый от уже занятых, в диапазоне 75–345°, чтобы не совпасть с красным цветом долгих запросов. Светлая тема использует светлоту 50%, чтобы подпись источника сохраняла контраст не ниже 5:1. На нажатой кнопке фильтра точка обведена цветом фона. Цвет задаётся через `oklch()` отдельно для светлой и тёмной темы и окрашивает подпись источника и точку на кнопке фильтра (полоса слева не окрашивается цветом инициатора и остаётся только у долгих запросов как индикатор задержки). Запросы без источника не окрашиваются. Быстрые запросы сворачиваются в группу, только если у них один инициатор. Фильтр не показывается, если ни у одного запроса нет источника. Копируется только SQL, без источника. Без HTTPS браузер скрывает Clipboard API, поэтому копирование идёт через временное поле внутри панели и `document.execCommand('copy')`; этот же путь пробуется, если Clipboard API отклонил запись. После копирования поле удаляется, фокус возвращается на кнопку. При открытии фокус остаётся на кнопке; уход фокуса не закрывает окно. Escape и кнопка закрытия возвращают фокус на кнопку сразу. Закрытие анимируется 150 мс.
- **Меню выбора шаблона** — выбор установленного шаблона DLE для браузера. При открытии фокус получает выбранный шаблон; уход фокуса закрывает меню. Escape возвращает фокус на кнопку после закрытия. Закрытие анимируется 130 мс.
- **Сброс кэша** — `CacheCleaner` удаляет файлы `engine/cache/system` и при `cache_type` файлы `engine/cache`, затем вызывает штатную `clear_cache()`; подкаталоги не очищаются. Как и в DLE, символические ссылки не проверяются: каталоги открываются по пути, ссылки на файлы удаляются как сами ссылки, ссылки на каталоги пропускаются. Проверка выхода за пределы `engine/cache` намеренно не добавлена: подменить каталог кэша ссылкой может только пользователь PHP, штатная очистка в админке DLE такую ссылку всё равно обработает, а вынесенный на другой диск `system` перестал бы очищаться (#17).

При reduced motion окна закрываются без ожидания анимации. Правила позиционирования, взаимодействия снаружи, выбора шаблона и работы с SQL остаются в соответствующих modules.

- **Подготовка зарегистрированных элементов** — `ComponentRegistry` владеет созданием, инициализацией поведения запроса и сборкой фрагментов панели. Настраиваемые элементы создаются перед инициализацией и перед выводом с нормализованными значениями из `ToolbarPreferences` через общий метод создания; defaults задаются только декларациями `Parameter`. После аутентификации и проверки доступа тулбаром хук `RequestComponent::initialize()` вызывается только для видимых элементов. Выбор шаблона создаётся при создании registry, до подмены шаблона DLE. Без доступа или при скрытой соответствующей кнопке cookie запросов сброса кэша и смены шаблона не обрабатываются. Смена шаблона передаётся одноразовой cookie `dle_toolbar_skin` с токеном DLE; PHP устанавливает HttpOnly-cookie `dle_skin` и перенаправляет на тот же адрес обычным GET, поскольку авторизация DLE завершается после выбора шаблона. Возврат к шаблону по умолчанию удаляет `dle_skin`. Cookie сброса кэша устанавливает скрипт кнопки на 60 секунд с немедленной перезагрузкой страницы.

- **Настройки** — `ToolbarPreferences` читает секции из `{prefix}_dletoolbar_settings` одним SELECT и держит результат только в текущем запросе. Каждая строка содержит `id`, уникальный `setting_key`, JSON в `setting_value` и `updated_at`. Вся форма сохраняется одним INSERT с `ON DUPLICATE KEY UPDATE`, без явных транзакций. При пустой таблице используются настройки по умолчанию; PHP-конфиг не читается. Форма показывает напоминание о несохранённых изменениях и закрепляет футер с кнопкой сохранения. Исходное состояние формы передаётся при отправке и сохраняется после ошибки проверки; при возврате всех значений и порядка компонентов напоминание исчезает.
- **Ошибки плагина** — общие `try/catch` находятся только в точках подключения YAML и во входном файле админки. Они журналируют исключение; отказ инициализации отключает панель, отказ админки показывает сообщение без уведомления об успехе. Компоненты работают напрямую со штатным API DLE.

- **Пользовательские ссылки** — повторяемые экземпляры типа `link` с ID `custom_<16 hex>`. Секция `instances` связывает ID с типом; порядок, видимость и параметры используют тот же ID. Удалённые экземпляры и их параметры исключаются при нормализации.
- **Адрес ссылки** — HTTP(S) или путь от корня сайта. `UrlTemplate` разрешает допполя только на полной новости, кодирует встроенные значения и проверяет итоговый URL. `NewsFields` получает исходные допполя найденной новости в `show.full.php`, сохраняет права просмотра и семантику заполненности штатной версии DLE.

- **Границы подключений** — `DebugLog::before($file)` / `after($file)` создают пару с полным временем исполнения (в том числе при вложенных парах и ручных логах). Автоматическая пара окружает include `engine/engine.php`. Начало сбора и вывод панели — отдельные отметки без выдуманных времён полного `init.php`/`main.php`. Источник вызова скрыт в UI; пометки кэша и списки файлов сохранены. Скроллбар диагностики повторяет SQL-панель.

- **Ранние и условные подключения** — SourcePath/DebugLog подключаются после защиты DATALIFEENGINE в init.php до functions.php. `includePath()` возвращает исходный путь без изменения области видимости include и выполняет before внутри условного выражения подключения. functions/sitelogin записываются с early-флагом до авторизации без чтения настроек; отображение ограничено штатным доступом и видимостью. after сопоставляет оригинальный путь с кэшированной копией по общему SourcePath и сохраняет признак кэша начала пары. main.php закрывается в точке рендера с подписью «до вывода».
