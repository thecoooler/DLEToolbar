# Правила проекта

## PHP и окружение DLE

- Не использовать `declare(strict_types=1);` в исходниках и тестах.
- Плагин работает внутри DLE. Константы DLE, штатные функции, глобальные объекты и поля конфигурации доступны по контракту CMS.
- Обращаться напрямую к `$config`, `$tpl`, `$Timer`, `$db`, `$member_id`, `$dle_login_hash`, `$js_array` и штатным API DLE.
- Не добавлять `function_exists`, `class_exists`, `method_exists`, проверки наличия констант (кроме защиты `DATALIFEENGINE` в начале файлов с исполняемым кодом: точек входа и представлений), проверки типов гарантированных объектов DLE и запасные реализации для отсутствующего окружения.
- Доверять структуре данных, которую возвращают штатные функции DLE. Не фильтровать повторно список шаблонов и не проверять метаданные шаблонов на соответствие контракту CMS.
- Обрабатывать исключения общим `try/catch` только в точках подключения плагина и во входном файле админки, записывать причину в журнал PHP. Не добавлять внутренние защитные обёртки компонентов, обработчики предупреждений, лишние абстракции и проверки. Не подавлять ошибки через `@` и не создавать фиктивные значения метрик.
- Сохранять условия, необходимые для поведения панели: видимость компонентов, выбранный шаблон, необязательные cookie и поля формы, пустая таблица настроек до первого сохранения.
- Хранить настройки в таблице ключ–значение через штатный `$db`: один запрос чтения и один INSERT с обновлением ключей при сохранении, без явных транзакций и отдельного класса хранилища. Кэшировать настройки только в переменной текущего запроса. Не читать прежний PHP-конфиг и не выполнять миграцию из файла.
- Сохранять проверку прав доступа, проверку CSRF-токена, нормализацию входных настроек и экранирование HTML.
- При работе с DOM обращаться напрямую к узлам, которые создаёт сам компонент, и к подключённым библиотекам. Учитывать действительно необязательные компоненты.

## Проверка изменений

- Использовать `dleplugin static` и `dleplugin test`.
- Для статического анализа указывать каталог установленного DLE, если анализатору нужны определения штатных классов и функций. Не добавлять проверки в исполняемый код ради анализатора.
